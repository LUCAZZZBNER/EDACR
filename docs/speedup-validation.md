## 改动

- 将原先 4 个串行处理“采集→构造”的 worker 拆为 4 个采集 worker 和 4 个构造 worker。
- 待构造任务存入 SQLite；构造阻塞时，采集仍能继续，未处理材料可以跨进程恢复。
- HTTP 同时请求上限由 4 改为 8，两阶段共享原有 REST/GraphQL 限流器；REST
  请求间隔仍为至少 0.8 秒，目标约 4,500 次/小时。归档下载仍最多 2 个并发。
- 取得 HTTP 并发槽后再执行发送节奏控制，避免等待并发槽的请求集中发送；重启
  恢复已保存额度。归档完整性检查移入线程，避免解压阻塞异步网络调度。
- 恢复时以 PR ID 集合匹配仓库评论，避免为每条评论重复加载完整 PR JSON。
